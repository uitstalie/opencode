## Phase 2: Investigation

Read the highest-value sources first:
- `README*`, root manifests, workspace config, lockfiles
- Build, test, lint, formatter, typecheck, and codegen config
- CI workflows, pre-commit / task runner config
- Existing instruction files (`AGENTS.md`, `CLAUDE.md`, `.cursor/rules/`, `.cursorrules`, `.github/copilot-instructions.md`)
- Local opencode config (`opencode.json`)

Prefer executable sources over prose. If docs conflict with config, trust the executable source.

Extract high-signal facts an agent needs:
- Exact developer commands (build, test single, lint, typecheck)
- Required command order when it matters
- Monorepo / package boundaries and entrypoints
- Framework quirks: generated code, codegen, build artifacts, special env loading
- Testing quirks: fixtures, integration test prereqs, flaky suites
- Conventions that differ from framework defaults

## Phase 4: Rules

Default rule to recommend for every project: `git-safety.md` (prevents dangerous git operations).

For projects with:
- TypeScript → also recommend `core-operating-rules.md`
- Web dependencies → also recommend `internet-rules.md`

Rules directory layout:
- `~/.config/opencode/rules/` — global rules
- `~/.config/opencode/shared-rules/` — shared rule pool
- `.opencode/rules/` — project-level rules

Mount rules via `opencode.json.instructions` using paths like `~/.config/opencode/shared-rules/<name>.md`.

## Phase 5: Scaffold

**Ask user to confirm before writing each file.** Never overwrite existing files.

### AGENTS.md
Include only repo-specific guidance. Every line should answer: "Would an agent likely miss this without help?"
